# Wails installer

A Go installer engine and a customizable Svelte setup screen for desktop applications. Install, upgrade, and uninstall your application through a separate Wails installer, or import the engine into your own project.

- Choose the installation directory.
- Offer launch at login and an explicit "Open application" action after installation.
- Show file-copy progress and cancel an installation.
- Upgrade an existing installation with rollback and keep personal files during removal.
- Change colors, typography, logo, sidebar, and footer.
- Set native window size limits and use a [borderless title bar](docs/customization.md#window-size-and-borderless-mode).
- Add Go hooks, a custom startup manager, or a custom process launcher.

The engine uses the Go standard library and works independently of the frontend. Existing Wails projects can keep their own frontend and call the service directly. The included component supports Svelte 4 and 5. The desktop example uses Wails v2. The [integration guide](docs/integration.md#wails-v3) also shows v3 service registration.

## Try the interface

With Node.js 22.12 or newer:

```sh
npm ci
npm run dev
```

Open the URL printed by Vite. The browser preview simulates installation, upgrades, uninstalling, cancellation, and launching. Select "Existing install" to try maintenance. It does not change files or startup settings. Its theme selector demonstrates CSS customization.

## Run a real installer

The [desktop example](examples/installer/README.md) includes a small Wails application you can compile into the payload. Install the [Wails native prerequisites](https://v2.wails.io/docs/gettingstarted/installation/) first.

```sh
npm ci
npm run build
cd examples/installer
go mod download
# Linux with WebKitGTK 4.1:
go build -tags 'desktop,production,webkit2_41' -o payload/lumen ./cmd/lumen
wails dev -tags webkit2_41
```

The repository also has portable commands for Linux with WebKitGTK 4.1, Windows, and macOS. Run these from the repository root after installing the Wails v2 CLI and native prerequisites:

```sh
npm ci
npm run build
npm run prepare:example
npm run check:bindings
npm run build:example
```

These commands build the sample payload for the current OS and package the importing Wails project. On macOS they create the sample `.app` bundle automatically. See [platform support and validation](docs/platform-support.md) for the native test matrix.

Build the target application and installer for the same OS and architecture. The payload placeholder is not an executable, so compile the sample or supply your own application before installing.

## Add it to your project

Install the Go library from this repository:

```sh
go get github.com/deedima3/wails-installer@main
```

The Svelte package has not been published to npm. Use a local package or archive for the frontend. For local development of the Go library, use a replacement as well:

```sh
# Run in your installer project's Go module. Use your actual clone path.
go mod edit -require=github.com/deedima3/wails-installer@v0.0.0
go mod edit -replace=github.com/deedima3/wails-installer=/absolute/path/to/wails-installer

# Prepare the component, then install it in your frontend.
cd /absolute/path/to/wails-installer
npm ci
npm run build --workspace @wails-installer/svelte
cd /absolute/path/to/your-installer/frontend
npm install /absolute/path/to/wails-installer/frontend
```

Create the engine and expose its service:

```go
payloadFS, err := fs.Sub(payload, "payload") // payload is an embed.FS
if err != nil { return err }
engine, err := installer.New(installer.Config{
    ID: "com.example.myapp",
    Name: "My app",
    Version: "1.0.0",
    Payload: payloadFS,
    Executable: "myapp", // "myapp.exe" on Windows
    AllowStartup: true,
})
if err != nil { return err }
service := installer.NewService(engine, directoryPicker)
// Include service in options.App.Bind for Wails v2.
```

Mount the UI with the functions generated by Wails:

```svelte
<script lang="ts">
  import { Installer, createClient } from '@wails-installer/svelte';
  import * as bindings from '../wailsjs/go/installer/Service';
  const client = createClient(bindings);
</script>

<div style="--installer-accent: #efb191; --installer-sidebar: #42312d">
  <Installer {client} />
</div>
```

The [integration guide](docs/integration.md) has the complete Go setup, directory picker, Wails lifecycle wiring, and packaging instructions. The [upgrade and uninstall guide](docs/lifecycle.md) covers ownership receipts, preserved data, rollback, and maintenance APIs. See [customization](docs/customization.md) for styling and extension examples, and [API reference](docs/api.md) for all exported settings and service methods.

## Platform behavior

| Platform | Default install directory | Launch at login |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\Programs\<id>` | `.lnk` in the current user's Startup folder, created with Windows PowerShell |
| macOS | `~/Applications/<id>` | `~/Library/LaunchAgents/<id>.plist`, active at next login |
| Linux | `~/.local/share/<id>` | `$XDG_CONFIG_HOME/autostart/<id>.desktop`, with `~/.config` as fallback |

Startup is optional and off by default for fresh installs. `Install` requires a new directory. `Upgrade` and `Uninstall` require an owned installation receipt. Changes are staged beside the destination; the previous version is kept as a backup until startup changes and receipt writes succeed. Personal files survive maintenance. Parent directories created during setup remain.

This release supports fresh per-user installs, upgrades, and uninstalling from the same setup UI or Go API. It does not register an entry in Windows Apps & Features or provide system-wide elevation, application-menu shortcuts, signing, or prerequisite installation. Payloads and maintained directories must contain regular files and directories, without symlinks. Close the application and run maintenance from a separate installer outside its install directory. See [limitations and recovery](docs/integration.md#limitations-and-recovery) before distributing an installer.

## Development

Go 1.22+ runs the engine. The Wails example pins Wails v2.15.0 and requires Go 1.25+. Node.js 22.12+ builds the frontend and runs its tests.

```sh
go test -race -cover ./...
go vet ./...
go -C integration/consumer test -race -v ./...
npm run check
npm test
npm run build
npm run build:demo --workspace @wails-installer/svelte
# Optional browser workflow tests:
npx playwright install chromium
npm run test:ui
```

CI is configured to run native engine tests, an independent Go consumer test, generated Wails binding checks, and Wails desktop builds on Linux, Windows, and macOS. The consumer test installs and launches a real executable. Windows checks also follow the generated startup shortcut, and macOS checks open a real `.app` and run its LaunchAgent command. Startup settings are isolated in temporary user directories. Actual logout/login behavior and signed release builds still need testing on the target machines. See [validation details](docs/platform-support.md).
